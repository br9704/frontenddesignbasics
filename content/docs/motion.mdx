## Curves decide how motion feels

<EasingCurves />

<EasingPlayground />

- **UI enters and responds with ease-out.** It starts fast, so it feels immediate, then settles.
  `cubic-bezier(0.22, 1, 0.36, 1)` is a strong default.
- **Things moving across the screen use ease-in-out.** They accelerate and brake like physical objects.
- **Avoid ease-in for UI.** It starts slowly, which reads as lag.
- **Linear** is for continuous motion only: progress bars, marquees, rotation.

## Durations

| What | Duration |
|---|---|
| Hover, press, toggle | 100–200ms |
| Menus, popovers, tooltips | 150–250ms |
| Modals, drawers, page sections | 250–400ms |
| Hero choreography, scroll scenes | as long as the story needs, but scrubbed to scroll |

Snappy beats smooth. If you notice the animation itself, it's probably too long.

## Choreography with GSAP

```ts
import gsap from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
gsap.registerPlugin(ScrollTrigger);

const mm = gsap.matchMedia();
mm.add('(prefers-reduced-motion: no-preference)', () => {
  gsap.from('.reveal', {
    y: 40,
    opacity: 0,
    duration: 0.8,
    ease: 'expo.out',
    stagger: 0.08,
    scrollTrigger: { trigger: '.reveal', start: 'top 80%' },
  });
});
```

`gsap.matchMedia()` is the cleanest way to give reduced-motion users a different path. Everything
inside only runs when motion is welcome, and it's reverted automatically when that changes.

## Smooth scroll with Lenis

```ts
import Lenis from 'lenis';
const lenis = new Lenis({ lerp: 0.1 });
lenis.on('scroll', ScrollTrigger.update);
gsap.ticker.add((t) => lenis.raf(t * 1000));
gsap.ticker.lagSmoothing(0);
```

Use smooth scroll on long, visual storytelling pages. Leave it off for docs, dashboards and anything
people scan quickly.

## Reduced motion is not optional

<ReducedMotionDemo />

People switch on reduced motion because movement can cause dizziness, nausea or distraction.
Swap movement for a fade, stop loops, and freeze canvases on a single good frame. The shader on this
site's home page does exactly that.

## Prove it moves

A screenshot proves nothing about motion. Capture two frames about 1.5 s apart (Playwright does it in
three lines) and compare them. Then capture again with `reducedMotion: 'reduce'` and confirm the
frames match.

```ts
const page = await browser.newPage();
await page.goto(url);
const a = await page.screenshot();
await page.waitForTimeout(1500);
const b = await page.screenshot();
console.log(Buffer.compare(a, b) === 0 ? 'STILL' : 'MOVING');
```

## How it works, in four ideas

<Flow
  caption="Each pixel runs this pipeline every frame. Nothing is stored between frames except time and the pointer."
  steps={[
    { title: 'Noise', note: 'smooth random field' },
    { title: 'Warp', note: 'noise bends noise', tone: 'accent' },
    { title: 'Threshold', note: 'field → ink shapes' },
    { title: 'Multiply', note: 'inks overprint paper' },
    { title: 'Grain', note: 'print texture', tone: 'ink' },
  ]}
/>

<Steps>
<Step>
### Noise

`noise(p)` returns smooth random values across space. Layering several octaves at doubling frequency
(**fbm**, fractal Brownian motion) gives natural, cloud-like detail.
</Step>
<Step>
### Domain warping

Feed noise into the *coordinates* of more noise: `fbm(p + fbm(p + fbm(p)))`. Straight bands turn into
ink swirling in water. Adding time to the inner calls makes it drift.
</Step>
<Step>
### Thresholds become ink

`smoothstep(a, b, f)` turns the continuous field into shapes with soft edges. Two thresholds with
slightly offset inputs make two "drums" of ink, misregistered like a risograph print.
</Step>
<Step>
### Multiply, then grain

Ink colours **multiply** onto the paper, so overlapping orange and blue go dark brown, as real ink
does. A per-pixel hash adds print grain, which also hides banding.
</Step>
</Steps>

```glsl
vec2 q = vec2(fbm(p + vec2(0.0, t)), fbm(p + vec2(5.2, 1.3) - t));
vec2 r = vec2(fbm(p + 3.0 * q + vec2(1.7, 9.2) + t * 1.4),
              fbm(p + 3.0 * q + vec2(8.3, 2.8) - t * 1.1));
float f = fbm(p + 3.2 * r);

float inkA = smoothstep(0.56 - uDensity, 0.66 - uDensity, f + 0.12 * r.x);
vec3 col = mix(uPaper, uPaper * uInkA, inkA * 0.92);   // multiply, like overprinted ink
col += (hash(uv * uRes + fract(uTime) * 91.0) - 0.5) * 0.045;  // grain
```

The full source is [`components/ink-field.tsx`](https://github.com/br9704/frontenddesignbasics/blob/main/components/ink-field.tsx),
including the pointer drag, the clear zone behind text, and the reduced-motion still frame.

## Write GLSL, or use a tool?

| You want | Use |
|---|---|
| A living gradient, tuned by eye | **ShaderGradient**: visual editor, then `@shadergradient/react` |
| A premium background or scene, fast | **GetLayers**: prompt + source library (MCP on the Full Stack plan) |
| Animated backgrounds as React components | **React Bits** backgrounds (`@react-bits/*`) |
| Something that is yours | Write it. Start from [The Book of Shaders](https://thebookofshaders.com) |

## Rules for shader backgrounds

- **MUST** keep text readable: mask the shader behind copy (this site's `clear` uniform) or put copy on a solid plate.
- **MUST** freeze on one good frame for reduced motion, and pause off screen.
- **MUST** cap DPR. Fragment cost scales with every pixel.
- **SHOULD** add grain or dithering. Smooth gradients band on 8-bit displays.

## Why it works

A shader background is texture, not decoration. Like paper stock in print, it sets the mood before a
word is read, as long as it stays behind the words.

AI generation is now a normal part of making a site: hero stills, texture, a looping background video, an
object turned into a 3D model. The craft hasn't changed. **You still art-direct**: the prompt is a brief,
and every output gets judged against the same principles as anything else on the page.

## Higgsfield: which model for which job

Higgsfield bundles many image, video and 3D models behind one MCP, so an agent can drive the whole
pipeline above. The routing below is what its MCP recommends (September 2026):

| Job | Model / tool | Notes |
|---|---|---|
| General image, typography, reference edits | `gpt_image_2_5` | The default for ordinary generation |
| Product, commercial, ad imagery | `marketing_studio_image` | Product shots and ad layouts |
| Portraits, fashion, editorial people | `soul_2` | With a trained Soul ID for a consistent person |
| General image → video | `seedance_2_5` | The default video model |
| Multi-shot, audio, motion transfer | `kling3_0` | Longer, directed sequences |
| 2K keyframes, mixed references | `minimax_h3` | Higher-resolution motion |
| Copy motion from a video onto a still | `hf_mult_motion_control` | "Genjutsu" motion transfer |
| Image → 3D model (GLB) | `generate_3d` | Drop the GLB straight into three.js / R3F |
| Clean-up | `upscale_image`, `upscale_video`, `remove_background`, `outpaint_image`, `reframe` | Finish assets for each placement |

<Callout type="warn">Higgsfield runs on credits. Check the balance and preflight the cost (the MCP's
`get_cost` option) before a batch, especially for video.</Callout>

Other tools in the same role: **GetLayers** for ready-made WebGL scenes and animated backgrounds,
**ShaderGradient** when a code-driven gradient beats a video, and **img2threejs** when you want an object as
editable code rather than a mesh.

## Prompts that work

<PromptAnatomy />

A good image prompt reads like a layout spec, not a mood. Six rules:

1. **Canvas first.** Size, aspect, and what the asset is for ("hero background, text will sit on the left third").
2. **Hex, not names.** `#0F3D2E` is a colour; "forest green" is a guess.
3. **Zones.** Say where things go: "upper third", "right side, behind the subject".
4. **One style lock, repeated.** The same style sentence on every prompt in a set is what makes a set look like a set.
5. **Keep text out of the image.** Image models still garble small type. Generate the picture, then set real text on top in HTML with real fonts.
6. **A safety line.** No real people, logos, flags or weapons unless you have the rights.

## Shipping AI motion on the web

```html
<div class="hero-media">
  <img src="/hero-poster.jpg" alt="" />          <!-- still frame: loading state + reduced motion -->
  <video autoplay muted loop playsinline preload="metadata" poster="/hero-poster.jpg">
    <source src="/hero.av1.mp4" type="video/mp4; codecs=av01.0.05M.08" />
    <source src="/hero.h264.mp4" type="video/mp4" />
  </video>
</div>
```

```css
.hero-media { position: relative; }
.hero-media > * { position: absolute; inset: 0; width: 100%; height: 100%; object-fit: cover; }
@media (prefers-reduced-motion: reduce) {
  .hero-media video { display: none; }          /* the <img> underneath stays visible */
}
```

- **MUST** set `muted` and `playsinline`, or mobile browsers won't autoplay.
- **MUST** ship a poster frame. It's the reduced-motion version and the loading state.
- **SHOULD** compress hard: short loops at `crf 28–32` look fine behind text. A background video over 3 MB is a performance bug.
- **SHOULD** check the loop point with two frames, like any other motion ([Motion → Prove it moves](/docs/motion#prove-it-moves)).

## Why it works

Generation removes the cost of *making* an asset, not the cost of *choosing* one. The sites that look
designed are the ones where someone wrote a real brief, rejected most of the output, and set the text
themselves.
